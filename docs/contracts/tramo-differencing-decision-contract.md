# TRAMO differencing decision (23-C)

`decide_tramo_differencing()` is the round-1 differencing decision unit: the
live `jdplus.tramoseats.base.core.tramo.internal.DifferencingModule.process`
over a fully-estimated `RegSarimaModelling`, transcribed from the pinned
jdplus 3.9.0 stack (item 23-C of `docs/tramo-seats-roadmap.md`). The unit owns
the whole ladder — the `comespd` size gate with its airline fallback, the
`step0`/`nextstep`/`initstep`/`maincondition`/`cond1`/`finalcond` loop with
its per-step Hannan-Rissanen start and warm maximum-likelihood
re-estimation, the `searchur` root scans behind `rmax`/`rsmax`, the
`FastKalmanFilter` `computeTMean` and the `isMeanCorrection` length table —
and decides the Changed/Unchanged result of the module stage (the
specification and mean updates of the description). Battery-stage replay
(`SeasonalityController`, `RegularUnder(+2)`/`SeasonalUnder(+2)`,
`SeasonalOverDifferencingTest`, the residual-ladder spectral peaks) is item
23-C.2; its landing facts are pinned inert in the golden. There is no Rcpp
boundary; the unit is C++-only.

```cpp
kalos::TramoDifferencingRequest q;    // interpolated, outlier-effect-free y
q.series = series; q.log_input = false; q.period = 12;
auto d = kalos::decide_tramo_differencing(q);  // Changed | Unchanged | Unprocessed
```

## Capture and corpus

`validation/evidence/native/tramo-differencing/` holds the double-captured
(DIFF/BAT/FULL header, request echo, fact and event lines, raw IEEE-754 bits)
oracle protocol of 25 cases driven through the live module against the pinned
jars (OpenJDK 21 with the G2 flags, `-Xlog:class+load` witnesses for the
module/battery classes) with the `--repro` byte-comparison gate.
`tests/jvm_tramo_differencing.h` is generated by
`tools/gen_tramo_differencing_golden.py`; the corpus is never altered. The
replay (10 DIFF + 12 BAT cases = 120 `diff_result`/`diff_info`/`after`/
`panel`/`mspec`/`lastmodel` lines) reproduces the live JVM facts bit for bit;
the 3 FULL cases and every battery line are inert stage facts pinned for
23-C.2/23-F. Java's `%.17g` pads the shortest round-trip decimal where C
expands the exact binary value (`0.97` versus `0.96999999999999997`), so the
replay compares numeric tokens by re-parsed bit pattern and every other
token verbatim (item 23-B bit-pattern discipline).

## Decision laws (bytecode → unit)

- **Envelope and gates.** Empty/non-finite series, period < 2 and
  non-positive values under the log channel throw `invalid_argument`.
  `comespd` runs `TramoUtility.autlar` on the probe model `(0,2,0)(0,seasonal
  ? 1:0)` (integer `log(n2*n2)`, `kmax = max(2*qTotal, k)`, the `n2 - n2/4`
  clamp, the 50 cap); below the gate the remark "default model selected (not
  enough obs.)" fires, `desc.setAirline()` applies unless the entry spec is
  already airline (`isAirline(seasonal)` → Unprocessed) and the mean is
  dropped. At period 12 with seasonal the fallback needs n <= 10.
- **initstep(b)** sets the probe orders ((2 or 1 at period 2),0,0 plus
  bp = 1 under seasonal when `b` and no differencing yet; else (1,1,1,1)
  under seasonal), builds the differenced correlation `w`, runs the raw
  HannanRissanen pipeline (`useDefaultIfFailed`: the −0.1 AR / −0.2 MA
  stationary-order fills on failure), and on `b` applies the
  `SarimaMapping.stabilize`/1.02-tolerance ladder: `spec.p > 1` or a
  modulus beyond 1.02 fails to the default fills, otherwise the model
  stabilizes. Warm ML (`err || ml || useml`) re-estimates through the
  qualified 23-B seam and sets `mlused`; `useml` is consumed per step.
- **step0** runs `initstep(true)`; with differencing already on the spec it
  overwrites `rmax`/`rsmax` with `phi1`/`bphi1`, then adds `searchur` UR
  counts against `ub1` on the mirrored AR blocks.
- **maincondition** decays `c -= 0.002`, sets `din = 1.005 - ub2` and reads
  the (phi1, theta1, bphi1, btheta1) quadruple: `|phi1 + 1| <= din` with
  `-phi1 > 1.02` forces `useml` (m = 1), else `|phi1 - theta1| > c`
  increments d; `|phi1| > 1.12` forces `useml`; the seasonal branch mirrors
  it with the `spec.bd == 0` gate and the `useml` rollback. **cond1** (iter
  0 only) fires on `|phi1 - theta1| >= c` with the seasonal side below `c`,
  skipped when `rmax, rsmax < 0.9`, incrementing the larger side.
  **finalcond** resolves m = 2 by `phi1 < bphi1` when `mlused` else by the
  positive larger scan maximum, and clamps `d <= maxd = 2`, `bd <= maxbd`.
  The loop runs `nextstep` until it returns false with the iter ≥ 5 exit.
- **computeTMean** differences `y` (with the last model stabilized), feeds
  `FastKalmanFilter.fastFilter` — the sticky Durbin-Magenau machine ported as
  `detail::pinned_fast_filter_residuals` — and takes the plain forward
  DataBlock sums `tmean = s / sqrt((ss * n - s * s) / n)`. The `d = bd = 0`
  branch runs on the raw response; a missing last model throws the pinned
  "Failure in the identification of the differencing orders", a failed or
  short machine the pinned "Non convergence in ESPDIF" — both turn into the
  airline fallback ("differencing selection failed"), never a throw.
- **isMeanCorrection** is the length table {<= 80: 1.96, <= 155: 1.98,
  <= 230: 2.1, <= 320: 2.3, else 2.5} on `|tmean| > threshold` against the
  response length; the description update replaces the spec iff the ladder
  end differs from the ENTRY orders (module spec replaces the whole
  orders) and follows `isMeanCorrection()` for the mean, marking Changed
  (both comparisons are against the entry state — see the dated appendix).

## Pinned machines and root causes

- **Filter orientation.** `RegArimaUtility.differencingFilter` hands the
  `BackFilter` the REVERSED polynomial while `mlj::apply_backfilter` reads
  coefficients ascending, so the JVM correlation equals the mlj correlation
  times `(-1)^(d + bd)` — one sign per reversed `(1 - B)` / `(1 - B^s)`
  factor. Verified element-wise against the live `BackFilter.apply` for the
  `d = 0, bd = 1`, `d = 1, bd = 0` and `d = bd = 1` orders; the parity flip
  is applied in both `initstep` and `computeTMean`.
- **searchur roots.** `Polynomial.roots()` runs `Roots_Factory.FASTSOLVER`,
  the `FastEigenValuesSolver` — NOT the DGEEV companion (`polynomial_roots`)
  the older units use; the 1-ulp `rmax` drift was rooted there. Within the
  ladder's degree domain (p ≤ 2, bp ≤ 1) `factorize` dispatches to the
  closed forms only: degree 1 `-c0 / c1`, degree 2 with `denom = 2a`,
  `disc = b*b - 4ac`, complex pair through `sqrt(-disc)` when `disc < 0`;
  the qr/chase branch is unported and degrees beyond 2 throw instead of
  substituting another engine. `ComplexType.abs` is the scaled modulus
  `m * sqrt(1 + (n/m)^2)` with the (0,0)/n == 0 shortcuts, not the correctly
  rounded `std::hypot`.
- **computeTMean fastFilter.** `FastKalmanFilter.fastFilter` is a different
  machine from `process(x)`: the warmup runs `tmax = max(arLen, maLen) - 1`
  steps with the sticky `fast` switch (all `|c4[j]| <= eps`), the h update
  every warmup step including after the switch, a NaN h as the abort, and
  the tail as the raw recursion `e[t] = x[t] + sum ar[j] x[t-j] - sum
  ma[j] e[t-j]`; the d_air innovations are bit-identical (84/84) on that
  transcription. The `process(x)` machine stays as the 23-B scan uses it.
- **Warm ML seam.** `TramoUtility.processor(true, eps).optimize` maps to the
  23-B warm Levenberg-Marquardt machine over the raw response with the
  constant meanCorrection column; JVM block order `[phi | bphi | theta |
  btheta]` versus the kalos sign-flipped AR convention is mapped at the
  seam. Converged-LM function-status counts (the 23-B qualification), and a
  non-finite landing follows the pinned Non-convergence path.
- **No demeaning of the module response.** `DataBlock.of` copies
  non-direct sequences; the ladder panel tmean on the raw y (d_qtr_noseas)
  pins that the module never mutates `y`.

## Battery replay (item 23-C.2)

`kalos::decide_tramo_differencing_battery` (include/kalos/tramo_differencing_
battery.hpp) replaces the inert battery stage lines with positive native
assertions over pinned estimation-state facts:

- **Kernel provenance.** The SeasonalFTest p-value is recomputed natively by
  `detail::f_upper_p(v, k1, k2) = incBeta(k2/2, k1/2, k2/(k2 + k1*v))`
  (src/special_functions.cpp), a bit-exact transcription of the pinned
  `SpecialFunctions` incomplete-beta + Lentz continued fraction (1000-
  iteration throw, 1e-300 tiny floor, fdlibm exp/log; the JVM
  DStatException/throw surface is the NaN p-value, matching the guards'
  dcmpg semantics). The golden is
  `validation/reference/fcdf_golden.txt` (18489 rows: a dense grid + specials
  plus the 90 corpus triples of the battery capture), double-captured
  byte-identical from independent JVM processes and replayed bit-pattern-for-
  bit-pattern in `test_special_functions` through `tests/jvm_fcdf.h`.
- **Active tiers.** SeasonalityController first pass (the `hasSeasonality`
  score written to `ctx.originalSeasonalityTest`, the m011+`setBq(1)`
  = (0,1,1,0,0,1) swap, the two seasonal-flip branches), the four battery
  steps (ru1 mean/quasi-unit-root gates and direct Changed; su1
  fixSeasonalRoots short-circuit + residual-ladder gate; ru2 lbp gate — a
  NaN p-value does NOT proceed — + zero-mean autocovariance count
  `pos12 >= freq || pos12 >= 9 || total >= 17`; su2 `bd!=1 && bq!=1 &&
  ost!=0` gate), the `ModelComparator` port (BIC preference over the
  `builder().build()` defaults, the exact 71/85 branch mapping,
  `checkAcceptable` + five tests), the per-state ports (`SpectralPeaks.
  hasSeasonalPeaks` length dispatch, the ladder score, the
  `SeasonalOverDifferencingTest` 0/1/2 code) and the second
  `compareReferenceModels` pass, which the JVM provably always leaves
  Unchanged because the reference model IS the live object.
- **Pinned boundary.** Estimation, the periodogram and the ModelStatistics
  algebra stay at the JVM boundary: every candidate panel, F triple, ladder
  stage fact and spectral-peak record is a captured getter of the live run
  (`validation/evidence/native/tramo-differencing-battery/`, 15 cases,
  1175 fact lines, double capture byte-identical, `SHA256SUMS.csv`
  verified). Candidate construction is asserted against the captured
  candidate stream (spec, mean, ok, consumption order 1..N-1); every
  Changed transfer must reproduce the candidate panel bit-exactly in the
  post-step state, every Unchanged step must freeze it.
- **Force-load evidence.** `SeasonalOverDifferencingTest` and
  `SpectralPeaks` class-load is witnessed via `-Xlog:class+load` during
  seven capture runs (`loadlog-*.txt`, `loadwitness.csv`): the battery never
  calls the over-side itself (15/15 `seas2` Unchanged lines pin that), so the
  90 captured over codes are observer force-calls whose codes the native
  port reproduces per state anyway.

## Fail-closed matrix

Battery additions: a calendar-bearing `SeasonalUnderDifferencingTest2` scan,
quasi-unit-root or ladder root scans above the ported closed-form degree, an
ru2 autocovariance window below 12 residuals, a missing or diverging
candidate snapshot, a null SeasonalFTest on the reference model, the
`fixSeasonalRoots`/`buildNewModel` estimation-failure or null-model paths
throw `std::runtime_error`; negative probes in the unit pin them.

- Empty/non-finite series, period < 2: `std::invalid_argument`; a
  non-positive observation under `log_input`: `std::invalid_argument`.
- A warm-ML landing that reaches the private `RegSarimaComputer.optimize`
  tail's unit-root cancellation restarts (`tryUrpCancelling` /
  `tryUrmCancelling` gates: orders plus the `|1 + phi(B)|`, `|1 +
  theta(B)| <= 0.1` threshold) throws `std::runtime_error` instead of
  silently skipping the pinned restarts — the corpus never reaches that
  state. A root scan beyond the ported closed forms throws likewise.
- Pinned ladder failures (non-converging ESPDIF, missing identification)
  follow the JVM catch into the airline fallback and never throw.

## Dated appendix — 23-F.4 debug correctives (2026-11-23)

The tramo-fit corpus (23-F F.4, `validation/evidence/native/tramo-fit/`)
supplied entry states the battery never had (initial-round calls on
non-zero entry orders, seasonal short-series failures) and exposed three
latent transcriptions, each fixed under the javap re-decode:

- **Changed-law comparison = ENTRY, not START.**
  `DifferencingModule.process(RegSarimaModelling)` compares the ladder-end
  `this.spec.getD()/getBd()` against the spec captured from
  `desc.specification()` BEFORE the ladder runs (javap offsets 200-206 slot
  8, comparison at 293-316); the mean compares `isMeanCorrection()` against
  `desc.isMean()` at the same tail. A ladder climbing from the
  initial-round `0,0` onto an entry `1,1` therefore answers UNCHANGED and
  leaves the description untouched (fit_tr3_air/fit_mean_air/fit_pure seam
  witnesses: `Unchanged 0,1,1,0,1,1`). The battery always entered at
  `0,0,0,0,0,0`, where start and entry coincide.
- **Airline shape.** `SarimaOrders.isAirline(seasonal)` tests
  `p == 0 && q == 1 && d == 1` (+ `bp == 0 && bq == 1 && bd == 1` under
  seasonality) and `ModelDescription.setAirline(seasonal)` writes
  `SarimaOrders.airline(freq)` = ARIMA(0,1,1)(0,1,1) — `bp = 0` — or
  `m011(freq)` = (0,1,1)(0,0,0) (fit_shortfail seam-6 `(1,0,1,0,0,0)` +
  mean on, seam-17 `(0,1,1,0,1,1)` + mean off). The landing had `p0 == 1`
  /`bp0 == 1` guards and a `spec_bp = seasonal` write; the hand probe
  `test_comespd_airline` had encoded the bug and was re-pinned.
- **Filter orientation stays parity inside this unit.** The fit RESPONSE
  recompute applies the reversed polynomial directly
  (`BackFilter.weightsToArray` emits reversed taps — see
  tramo-fit-contract.md); the two forms are entry-wise equal up to the
  sign of zero, and the ladder consumes `w` only through means,
  cross-products, roots and comparisons, where the parity form is
  corpus-proven on every panel. The 23-C `initstep`/`computeTMean` parity
  flip therefore stands unchanged.
