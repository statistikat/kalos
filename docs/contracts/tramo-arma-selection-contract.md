# TRAMO arma selection (23-D)

`select_tramo_arma()` is the round-1 arma selection unit: the live
`jdplus.tramoseats.base.core.tramo.internal.ArmaModule.process` with its
`ArmaModelSelector` FastBIC machine, transcribed from the pinned jdplus 3.9.0
stack (item 23-D of `docs/tramo-seats-roadmap.md`). The unit owns the whole
module stage — the `comespa` size gate with its default-model and
already-airline branches, the `calcmaxspec` candidate envelope, the
three-stage selector grid (stage-1 seasonal AR-block grid on the base
(3,0)(0,0) model, stage-2 ARMA grid on the preferred model, stage-3 seasonal
grid), the per-candidate HannanRissanen fit + `isStable(true)` + FastBIC
sort, the `getPreferred` pick, the `mergeInto` watermark merge into the
five-row `hrModels` panel and the eleven-gate `select()` tie-break — and
decides the Changed/Unchanged/Unprocessed/Failed result of the module stage
with its ProcessingLog lines. There is no Rcpp boundary; the unit is
C++-only. It has no relation to the X-13 items 21-E/F engines.

```cpp
kalos::TramoArmaSelectionRequest q;
q.residuals = ols_residuals;   // RegArimaUtility.olsResiduals(regarima())
q.nobs = nobs;                 // regarima().getObservationsCount()
q.period = 12; q.p0 = 0, q.d0 = 1, q.q0 = 1, q.bp0 = 0, q.bd0 = 1, q.bq0 = 1;
auto s = kalos::select_tramo_arma(q);  // Changed | Unchanged | Unprocessed | Failed
```

## Coordinate map (module → unit)

The selector input is NOT the response series: the live module reads
`RegArimaUtility.olsResiduals(desc.regarima())`, the regression- and
outlier-adjusted, mean/log-corrected residual block (length `n − (d +
period·bd)` for the airline shapes). That block is REQUEST DATA owned by the
upstream regression stage; the golden captures pin the hand-over bit-exactly
(`resvals` lines). `nobs` rides separately because `comespa` sizes on
`regarima().getObservationsCount()`, not on the residual length. The
`ArmaModule` builder pins map to the request defaults: seasonal = true,
acceptWhiteNoise(wn) = false, modelsCount = 5; the maxP/maxQ/maxBp/maxBq
caps are NOT builder state but the `calcmaxspec` output of the module.
(Dated 2026-11-23, 23-F.4 decode: the live `seasonal` operand is the
`TramoKernel` module factory reading `ctx.seasonal` at module creation —
the request carries that evolving context per call; "true" was the corpus
default, not the law. The 23-D corpus never created a module under
`ctx.seasonal = false`.)

## Capture and corpus

**Engine witness.** The corpus forces the HannanRissanen class load
(`-Xlog:class+load`, `load-witness.csv`, `loadlog-a_base.txt`,
`loadlog-a_srw.txt`): HannanRissanen, `core.arima.estimation.
FastKalmanFilter`, `core.arima.AutoCovarianceFunction` and the selector/module classes
load 3× (probe replay + module path), while `RegSarimaComputer`,
`GlsSarimaComputer`, `internal.HannanRissanenInitializer` and
`levmar.LevenbergMarquardtMinimizer` load ZERO times on every witnessed run.
The selection stage is HR + fast conditional BIC; no maximum-likelihood
machine is involved, decoded and witnessed.

`tests/jvm_tramo_arma.h` is generated by `tools/gen_tramo_arma_golden.py`
(the `probe_sha256` header pins the probe revision the corpus was captured
with); the corpus is never altered. 14 cases replay the module-level fact
lines (`direct_sel`, the five `dpanel` panel rows, `arm_result`, `after`)
and the full ProcessingLog event sequence bit for bit; the quarterly case
pins the D11 refusal; the constant-series case pins the upstream
`olsResiduals` NPE (record only, no hand-over exists). The `pcnt`/`maxspec`
gate lines and the `resvals` vectors ride along inert. Java's `%.17g` pads
the shortest round-trip decimal where C expands the exact binary value, so
the replay compares numeric tokens by re-parsed bit pattern — including the
CInfo detail tokens where the key glues to the value (`b2=-2.146…`), which
are split at the first `=` and re-parsed per half (item 23-B discipline).

## Decision laws (bytecode → unit)

- **Gate.** `maxInic(period)` = 1 at period 2, 2 at 3, else 3. `comespa`
  decrements `m` from `maxInic` while `checkespa(freq, n, m, d, bd,
  seasonal)` fails: `TramoUtility.autlar(n, calcmaxspec(m)) >= 0` AND the
  bare sign `autlar(n − p − period·bp, calcmaxspec(m) with p = bp = 0) >= 0`
  — the pinned bytecode keeps NO further subtraction (the `n = 56` flat
  capture discriminates). Monthly `m ∈ {3, 2, 0}`: the seasonal airline
  enters at `n >= 68` (pcnt 3), `62 <= n <= 67` gives 2, `<= 61` gives 0;
  m = 1 is never tested at monthly. `pcnt == 0` fires the remark "default
  model selected (not enough obs.)", then `SarimaOrders.setDefault()` +
  Changed unless `isAirline(seasonal)` already holds (→ Unprocessed).
- **`calcmaxspec(freq, m, d, bd, seasonal)`** is the candidate envelope
  (maxP/maxQ/maxBp/maxBq): monthly `m ∈ {1,2,3}` gives p = q = m and, when
  seasonal, bp = bq = 1 UNCONDITIONALLY on bd; `m = 4` (impossible at
  monthly) gives (3,3)(2,2). (`checkmaxspec`, the gate's probe model, keeps
  its own table where `bp = 1` only fires at `bd == 0` — a real
  divergence between the two tables in the pinned jar.)
- **Selector stages.** Stage 1 (seasonal only) grids bp 0..maxBp × bq
  0..maxBq (outer bp) on the base model (p = 3, q = 0); an empty panel
  retries with p = 1 on the same candidates; still empty → null. `preferred
  = getPreferred` (first candidate with a non-zero parameter count, tmp[0]
  when the acceptwn flag is set, null for an empty panel — an all-zero
  panel throws the pinned AIOOBE into Failed). The merge into `hrModels`
  is gated on `base.getP() <= maxP` (3 ≤ maxP at monthly, so it fires).
  Non-seasonal entries skip stage 1 (`preferred = base.clone()`). Stage 2
  grids p 0..maxP × q 0..maxQ (outer p) on `preferred`, re-preferred,
  merged unconditionally. Stage 3 (seasonal) re-grids the seasonal blocks
  on the new preferred and merges (no re-preferred after it).
- **Per-candidate fit.** `HannanRissanen.process` (the qualified
  `detail::hannan_rissanen_pipeline` seam, always `useDefaultIfFailed`
  false — exceptions leave the candidate Failed), then `isStable(true)` on
  the four blocks (`detail::check_roots` at bound 1.0 after trailing-zero
  trim), then the FastBIC. The panel sorts by `List.sort(naturalOrder)` =
  `Double.compare` BIC ascending (NaN greatest) and is stable:
  `std::stable_sort` with the matching total order.
- **FastBIC** is `new FastKalmanFilter(model).fastProcessing(residuals,
  getParametersCount())` = `log(ssq/n) + k·log(n)/n` with ssq the forward
  DataBlock fold of v² over FINITE innovations only, n the full innovations
  length and both logs the fdlibm transcriptions. The innovations are the
  pinned `detail::pinned_fast_filter_residuals` machine (23-C) — reused
  bit-for-bit; no estimation engine beyond HR is touched.
- **`mergeInto(src, dst)`** keeps the five-row panel ordered by BIC:
  watermark `j` advances past consumed slots; per source row scan `k =
  j..4` — a null slot inserts and lifts the watermark, equal orders are
  skipped, a strict `dst.BIC − src.BIC > 0` (`Double.compare`-signed,
  NaN-safe) shifts the tail down and inserts, otherwise the row stays
  unplaced and the watermark does NOT move.
- **`select(d, bd)`** scans the panel (all-null → pinned AIOOBE → Failed;
  n = 1 returns hr[0]) with eleven gates G1–G11 over the candidate orders
  and BIC gaps against the running best, the alpha tiers `diff < 0.003 →
  0.0625`, `diff < 0.03 → 0.25`, else 1 scaling the accept budgets {0.01,
  0.0025, 0.0075}, and the per-accept budget relief `a/b/c −= bic −
  bic0`. A final accept with zero parameters and `best < nmodels − 1`
  returns `hr[best + 1]` (the white-noise fallback), else `hr[best]`. The
  non-seasonal return is `hr[0]` with its own fallback rule (`hr[1]` when
  hr[0] has no parameters, `!acceptwn` and `hr[1] != null`); seasonal
  entries run `select`.
- **Module outcome.** equals `spec.doStationary()` (the p/q/bp/bq copy) →
  Unchanged; else `setSpecification(SarimaOrders.of(sel, d, bd))` +
  Changed and the info line "selected model: (p,q)(bp,bq)" carrying the
  CInfo detail (best + five model rows + five BICs). Any RuntimeException
  inside the stage (selector null, HR exception, fast-filter abort) leaves
  the specification as-is and fires the remark "arma selection failed"
  (Failed).

## Fail-closed matrix

- Non-monthly request (`period != 12`), empty residual block, non-finite
  residuals: `std::invalid_argument` (register D11, monthly-first
  envelope). The unit never falls back to the X-13 arma selection (21-E/F).
- Pinned JVM failures inside the stage — HannanRissanen pipeline
  exceptions, fast-filter aborts (the `nullopt` mirror of the pinned
  ArimaException/AIOOBE surface), the null/empty-panel selection — follow
  the live RuntimeException catch into Failed, never a throw and never a
  silent specification change.
- The constant series makes `olsResiduals` throw an NPE INSIDE the module
  try — the JVM catches it into Failed ("arma selection failed", the
  captured `arm_result` line) — but no residual hand-over exists to drive
  the unit, so the golden pins it as a record-only case; the native unit's
  envelope refusals (empty block, non-finite block, non-monthly period)
  are pinned by negative probes in `test_tramo_arma`, and the Failed
  transfer itself by the captured `arm_result a_const Failed` line
  (inert).

## Not delivered or claimed

The OLS residual computation itself belongs to the upstream regression
estimation stage (23-F wiring); this unit consumes the hand-over the golden
pins. The multi-round kernel driver that re-feeds the module a re-estimated
description stays 23-F, and the non-monthly domain stays behind D11. The
`m = 4` calcmaxspec shape (quarterly territory) is transcribed but
unreachable through the monthly envelope. The Rcpp boundary is not
delivered.
