# TRAMO round-0 outlier scan (23-B)

`scan_tramo_outliers()` is the round-0 decision unit of the pinned
`jdplus.tramoseats.base.core.tramo.internal.OutliersDetectionModule`: the
`make()` size gate, the `ModelDescription` pre-stage (interpolation, log
transformation, the differenced design), the `FastOutliersDetector` round-0
`estimateModel`, the `FastOutlierDetector` scan (initmodel, per-factory T and
coefficient tables, `searchMax`) and the `|maxT| >= cv` gate. It observes the
FIRST scan round only — the committed corpus round-0 facts are the oracle.
The multi-round driver (further rounds, the backward removal step, the
maxRound/maxOutliers exits, the robust AO+LS pre-stage) stays open under
register **D3**; its corpus traces are collected as decision-brief evidence
below. There is no Rcpp boundary; the unit is C++-only.

```cpp
kalos::TramoOutlierScanRequest q;          // raw series, fixed orders,
q.y = series; q.cv = kalos::tramo_critical_value(n);   // the calcCv grid
auto d = kalos::scan_tramo_outliers(q);    // Failed | Unchanged | Selected
```

## Capture and corpus

`validation/evidence/native/tramo-outlier-scan/` holds the double-captured
(SCAN header, request echo, fact and event lines, raw IEEE-754 bits) oracle
protocol of 26 cases run through the PUBLIC entry point
`OutliersDetectionModule.process` against the pinned jdplus 3.9.0 jars, with
the `--repro` byte-comparison gate (transform-decision precedent). The
golden header `tests/jvm_tramo_outlier_scan.h` is generated by
`tools/gen_tramo_outlier_scan_golden.py` from that corpus; the corpus itself
is never altered. Every replay double rides the bit-exact corpus values; all
dev-stage JVM dumps quote raw getters at Java `%.17g` PLUS the IEEE-754 bit
pattern (Java's `%.17g` renders some doubles one digit away from the C
rendering of the same bits — bit-level comparison is the only sound gate).

## Decision laws (bytecode → unit)

- **`make()` gate**: `TramoUtility.autlar`-based `comatip < 0` (n below the
  need formula) or a false `FastOutliersDetector.process` precheck maps onto
  `Status::Failed`; the odmInfo fact (`cv`, factory types, outliers) is
  logged on every status. `comatip` is `v5 < 0 || v6 < 0 ? 1 : 0` (the
  JVM compares inverted; the bytecoded branch order is pinned).
- **Pre-stage**: `AverageInterpolator.cleanMissings` (interpolation is the
  pinned recipe; missings without it fail closed), the log transformation of
  the decision pre-stage, then the differenced design with columns in the
  pinned order [missing-observation convolutions, constant, pre-registered
  outlier convolutions]. Interpolated missings STAY in the design as free
  columns after interpolation. TC prespec columns use the pinned
  repeated-multiply decay fill, AO/LS the unit convolution; an out-of-domain
  prespec variable never reaches the design (the module exclusion is a
  guarded no-op).
- **estimateModel round 0**: `OlsComputer.compute(LinearModel)` (the
  pivoting Householder machine, rcond 1e-9) over the design; residuals by
  literal `calcResiduals`; `HannanRissanen.process(residuals,
  specOrders.doStationary())`; the install is
  `SarimaMapping.stabilize(hrModel)` — the HR landing is a raw JVM
  coordinate vector that often sits OUTSIDE the stability region, so the
  stabilize is not the identity and the module tail runs
  `optimizeModel` from the installed model (the `hr.stabilized` trigger is
  required). Otherwise the ML flag runs the
  `ConcentratedLikelihoodComputer.DEFAULT_COMPUTER` compute +
  `updateLikelihood`, which overwrites the stored residuals with the GLS
  ones.
- **initmodel** (`jd_FastOutlierDetector`): `stmodel/ur` from
  `arima.stationaryTransformation()`; `cl = DEFAULT_COMPUTER.compute`;
  `el` = full residuals (empty design coefficients → plain `cl.e()`, else
  the `FastKalmanFilter(stmodel)` innovations of `calcResiduals`);
  `mad = Mad2(50)(el)`.
- **FastKalmanFilter** (pinned machine, `pinned_fast_kalman_residuals`):
  ctor eps 1e-12; window `dim = max(arOrder, maOrder + 1)` seeded from
  `acf.values(dim)`; `tx(c0)` is an IN-PLACE left-shift whose new tail is
  `-Σ_{j≥1} phi[j] * c0[dim - j]` over the raw AR polynomial array — a
  one-character-wrong shift is a 1-ulp el drift, hence the 83/83 bit-exact
  pin against the JVM dump.
- **pi weight columns** (`processOutlier`): `w = pi.times(rep.filter).
  getWeights(m)` with `pi = ar/ma` of the full model. `RationalBackFilter.
  times` runs `Polynomial.SimplifyingTool` cross-cancellation BEFORE
  multiplying: `simplifyExact` (=`LeastSquaresDivision.divide` + `isExact`,
  i.e. the divisor shifted across n rows, `Householder2` least squares at
  rcond 0, exact iff `ssqErr / m < sqrt(epsilon)` with the dcmpg reading
  that treats NaN as exact) fires for the LS (`1 - B`) and SO (`1 - B^12`)
  denominators, so those columns run on the LEAST-SQUARES QUOTIENT of the
  pi numerator (with its float residue, e.g. −5.07e−17 coefficients) over
  the plain MA; AO (constant denominator) skips the simplifier and TC
  (`1 − cB`) misses the roots-pass `|pi(1/c)| < 1e-12` window by orders of
  magnitude, leaving both unsimplified. The unit pins this via
  `pinned_ls_divide`; the general roots pass (degree > 2 exact miss, or a
  linear denominator inside the window) throws instead of approximating.
  Skipping the cancellation costs 2 ulp on the SO columns and 17 ulp on
  `sc_excl`'s LS pick — it is NOT noise-tolerant.
- **T table**: `m = |el| + ur.deg` rows; column-major `searchMax` over the
  per-factory zones (AO 0/0, LS 1/1, TC 0/1, SO 24/24 exclusions), gate
  `⇔ !(|maxT| < cv)` (the JVM compares with the `<` flavour, so a NaN maxT
  passes the gate); the incremental ssq/window accumulator and the T value
  `coef * sqrt(ssq) / mad` follow `processOutlier` line by line; the
  `rep.correction` branch is gated on `ur.getDegree() == 0` and the request
  keeps the differencing positive, so it stays dormant by pin.

## Fail-closed matrix

- frequency ≠ 12, non-positive lengths/orders, d + bd = 0, negative or
  non-finite values without the missing pattern: `std::invalid_argument`.
- missing observations without `interpolate`: `std::invalid_argument` (the
  pinned recipe always interpolates).
- pre-registered SO: `std::invalid_argument` (the SO prespec fill loop is
  outside the transcribed surface).
- warm re-estimation with a non-constant design (non-invertible HR landing
  stabilized off the unit circle combined with a prespec/missing design):
  `std::runtime_error` — the qualified Levenberg-Marquardt seam is
  design-free/constant-column only and the multi-column GLS-profiled
  objective is its own future slice. Corpus case `sc_pexao47` pins the
  throw; the JVM lands its (bit-dumped) landing + `drv.coeff` pair.

## Implementation-actual deltas at landing (23-B)

- Java/C `%.17g` divergence: three suspected 1-ulp drifts (OLS mean
  coordinate, sc_gs2 maxT, OLS b for sc_multi) turned out to be rendering
  artifacts — the bits were equal all along. The replay and dev gates
  compare IEEE-754 bits, not `%.17g` text.
- `OlsComputer.compute` (not `OlsComputer`-via-`OlsAlgorithm`) is the round-0
  OLS machine: `LeastSquaresResults.getCoefficients()` of the pivoting
  Householder solve, matching `pinned_ols_coefficients`.
- The `SimplifyingTool` cross-cancel is load-bearing at the ulp level; the
  earlier "documented deviation" (skipping it) is retired — see the law
  above.
- `pinned_fast_kalman_residuals` tx shift fixed against the JVM dump
  (83/83 bit-exact on JVM-exact acf inputs).
- ASan caught the `HouseholderWithPivoting` free-column init-norm shape:
  the JVM norms each free column over ROWS [nfixed, m) (a `DataPointer` at
  `nfixed * (m + 1)` advanced by `m` per column — `ssq` leaves the pointer
  in place, `move(m)` steps the column). The first transcription normed
  from the DIAGONAL row, which read one element past the storage for a
  two-column design at nfixed = 0. Fixed to `k * m + nfixed`; the pivot
  decisions on the whole corpus are unchanged (bit-exact replay and the
  4368-check OLS sweep invariant before and after).

## D3 decision-brief evidence (round-0 vs multi-round)

The captured corpus already exhibits the three divergence shapes the D3
brief must settle: `sc_so` and `sc_spanout` round-0-select [60, 0] /
[60, 3] (|maxT| ≈ 10.59 both, bit-exact here) yet the live multi-round
driver empties the set — final fact lines `scan_status Unchanged` with
`outliers[]`; `sc_spannone` scans with bounds collapsed by an out-of-range
selector and reaches `searchMax` with no admissible cell (the probe's raw
`getMaxTStat` throws, the module maps to no selection). The unit is pinned
to round 0 and the corpus final states above are asserted only as
documented divergence (`divergent=1`), never reproduced.
